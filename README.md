# Stayora – property booking app (desktop-first, responsive)

React 19 + Vite booking app for a single property listing, with its **Photo tour** and **Lightbox** overlays. Optional layered Node API (`backend/`: Express, SQLite, zod, tests).

## Run
```bash
npm install
npm run dev            # http://localhost:5173
cd backend && npm install && npm start   # optional API on :4000 (Node >= 22.13); Vite proxies /api
npm run lint && npm run build
```

## Views & behaviour
- **Navbar** – search pill (Where / When / Who panels, live summary, Search button), menu and language popovers; outside-click, Esc, arrow keys, focus return.
- **Listing** – header, 5-photo hero grid, details, amenities (+ modal), calendar, booking card, reviews (+ modal), location, host, things to know, nearby stays.
- **Photo tour** – `?modal=PHOTO_TOUR_SCROLLABLE`; room thumbnails with scroll-spy, sticky room headings; opened from *Show all photos* or any hero photo (scrolls to it).
All listing photos are original illustrations generated by `tools/make_photos.py` and stored in `public/photos`, `public/nearby` and `public/sleep`. Replace the JPGs (same file names) with your own photos at any time; listing details, host, reviews and nearby stays are sample content.
- **Lightbox** – `&modalItem=<index>`; prev/next buttons, `←` `→`, `Esc` back to the tour, filmstrip, counter, fullscreen.
- URL is the state, so Back / Forward / refresh work.

## Accessibility
Every modal overlay (photo tour, lightbox, amenities, reviews): `role="dialog"`, `aria-modal`, accessible name, focus moves in on open, Tab trapped, `Esc` closes, focus returns to the trigger (`src/hooks/useDialog.js`). Popovers (navbar panels, date and guest pickers) have `role="dialog"` and an accessible name and close on outside click or `Esc`; they do not trap focus. Clickable items are real buttons, except the modal backdrops, which close on click (`Esc` also works). Visible focus rings; a global `prefers-reduced-motion` rule disables animation and smooth scrolling.
